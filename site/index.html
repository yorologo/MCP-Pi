Control y Seguridad

¿Por qué existe MCP-Pi?

Cerrar la brecha de confianza entre agentes autónomos e infraestructura de producción.

✕

El riesgo: Dar acceso directo a la IA

Conectar un asistente de IA (Claude Desktop, Cursor, agentes autónomos) directamente a tus servidores mediante SSH o shell libre es peligroso: un desliz de prompt injection o una alucinación puede alterar bases de datos, ejecutar comandos destructivos o extraer secretos sin supervisión.

✔

La solución: Aislamiento físico y estricto

MCP-Pi se sitúa en medio como un appliance de hardware independiente (un Raspberry Pi de bajo consumo). La IA solo puede comunicarse con el gateway mediante el protocolo Model Context Protocol (MCP). Cada llamada es interceptada, verificada y auditada antes de tocar cualquier equipo de destino.

Menor Privilegio Real

La IA solo ve y ejecuta las herramientas y proyectos autorizados para su ID específico.

Transporte SSH Anclado

Huellas criptográficas de host verificadas. Se rechazan suplantaciones de servidores remotos.

Kill Switches Globales

Desactiva escrituras o ejecución de comandos instantáneamente sin apagar los servicios de consulta.

Límites Estrictos de Seguridad

No Ejecuta Payloads Sin Autorizar

Cualquier herramienta fuera de catálogo o sin grant produce una denegación inmediata.

No Oculta Errores ni Falla Abierto

Discrepancias de clave de host, timeouts o caídas de red terminan en cierre seguro.

Sin Dependencia de Servicios Cloud

100% autónomo y privado en tu red local. Tus datos e historial nunca salen de tu control.

Sin Bypass de Sudo

El appliance no contiene reglas permisivas de sudoers ni credenciales maestras.

Guía de Instalación y Uso Rápido

Instala y configura MCP-Pi en minutos directamente desde la última versión compatible.

Requisitos Verificados

  • Hardware: Raspberry Pi (ARMv6, ARMv7, ARM64) o Linux x86_64
  • Sistema Operativo: Linux con systemd (Raspberry Pi OS, Debian 11/12, Ubuntu)
  • Software: OpenSSH client y SQLite 3.35+ (Cero dependencias de Python o Node)

1. Descargar la release oficial

Descarga el paquete inmutable empaquetado para tu arquitectura desde GitHub Releases.

curl -LO https://github.com/yorologo/MCP-Pi/releases/latest/download/MCP-Pi-linux-armv6.tar.gz

2. Verificar checksums SHA256

Comprueba la integridad criptográfica del paquete antes de la extracción.

sha256sum -c SHA256SUMS

3. Ejecutar el instalador canónico

El script install.sh configura los usuarios del sistema, servicios systemd y la base de datos inicial.

sudo ./install.sh && sudo systemctl status mcp-gateway.target

4. Conectar tu cliente MCP

Añade la configuración en Claude Desktop (claude_desktop_config.json) o tu agente preferido: 

{
  "mcpServers": {
    "mcp-pi": {
      "command": "/home/mcp-gateway/mcp-gateway/bin/mcp-gateway-client-stdio",
      "args": ["--client", "claude-desktop"]
    }
  }
}

Resolución de Dudas

Preguntas Frecuentes

Respuestas directas a dudas comunes de arquitectura, seguridad y despliegue.

¿Por qué alojar el gateway en un Raspberry Pi independiente? ▼

El aislamiento físico garantiza que incluso si un agente de IA se descontrola o sufre un prompt injection severo, no tiene acceso a las claves maestras ni al hardware del servidor central. El Raspberry Pi actúa como una aduana insobornable.

¿Cómo se previenen ataques de inyección de comandos? ▼

MCP-Pi no pasa comandos de texto a una shell abierta a menos que se use la herramienta 'run_command' con el switch 'shell_enabled=true' y un grant explícito. Las mutaciones de archivos usan primitivas atómicas del sistema de archivos con validación estricta de límites de proyecto.

¿Qué ocurre si cambia la clave de host SSH del servidor remoto? ▼

MCP-Pi falla cerrado inmediatamente. Si la clave no coincide con el pin criptográfico registrado, la conexión se rechaza para evitar ataques Man-in-the-Middle, registrando una alerta en la auditoría.

¿Requiere conexión a internet o servicios externos? ▼

No. MCP-Pi funciona de manera 100% local en tu red privada. No envía telemetría ni depende de APIs de terceros para evaluar políticas o gestionar el registry.

¿Cómo se auditan las operaciones? ▼

Todas las peticiones recibidas, aprobadas y denegadas se escriben en la base de datos SQLite interna con marcas de tiempo ISO, identificadores de cliente, herramientas invocadas y códigos de resultado.

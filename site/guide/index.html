Guía de Instalación y Uso Rápido

Usa un paquete publicado compatible y completa el bootstrap antes de conectar clientes.

Consulta requisitos y versiones publicadas · v1.6.11

Requisitos Verificados

  • Paquete publicado de referencia: Linux ARMv6 (v1.6.11). Otras arquitecturas requieren un binario compatible o compilación desde código con Go.
  • Host Linux con systemd y permisos administrativos. Revisa las precondiciones del instalador; no todas las distribuciones han sido validadas.
  • Herramientas del sistema, curl, tar, sha256sum y cliente OpenSSH. El paquete incluye SQLite en Go; no requiere Python, Node ni compilador.

1. Descargar la release oficial

Ejemplo fijado a v1.6.11 / commit 5172705639d8. Descarga paquete y checksum; revisa GitHub Releases para otras versiones.

curl --fail --location --remote-name https://github.com/yorologo/MCP-Pi/releases/download/v1.6.11/MCP-Pi-1.6.11-linux-armv6-5172705639d8.tar.gz &&
curl --fail --location --remote-name https://github.com/yorologo/MCP-Pi/releases/download/v1.6.11/MCP-Pi-1.6.11-linux-armv6-5172705639d8.tar.gz.sha256

2. Verificar checksums SHA256

Detente si falla el checksum. Solo después extrae el paquete y entra en su directorio. El checksum comprueba integridad; no es una firma independiente.

sha256sum -c MCP-Pi-1.6.11-linux-armv6-5172705639d8.tar.gz.sha256 &&
tar -xzf MCP-Pi-1.6.11-linux-armv6-5172705639d8.tar.gz &&
cd MCP-Pi-1.6.11

3. Ejecutar el instalador canónico

En el directorio extraído, install.sh valida precondiciones y configura servicios, Registry y bootstrap de Admin. Lee el resultado antes de continuar.

sudo ./install.sh

4. Configurar Admin, permisos y cliente

Admin escucha en loopback. Completa el bootstrap según el README, añade Target y clave SSH verificada, Project y grants del cliente. Usa Check Effective Access. ChatGPT y Gemini requieren sus integraciones y credenciales externas; no basta con copiar una ruta local.

Configurar clientes y permisos

sudo -u mcp-gateway mcp-gateway status
sudo -u mcp-gateway mcp-gateway doctor

Resolución de Dudas

Preguntas Frecuentes

Respuestas directas a dudas comunes de arquitectura, seguridad y despliegue.

¿Por qué alojar el gateway en un Raspberry Pi independiente? ▼

Un equipo dedicado separa el despliegue del gateway de tus destinos. La protección depende de permisos, claves y administración segura; no garantiza aislamiento frente a toda operación autorizada ni frente a un host comprometido.

¿Cómo se previenen ataques de inyección de comandos? ▼

Prefiere herramientas estructuradas o tareas permitidas. run_command requiere autorización y shell habilitada, pero ejecuta shell de confianza: el proyecto determina alcance de autorización y directorio inicial, no un sandbox de archivos.

¿Qué ocurre si cambia la clave de host SSH del servidor remoto? ▼

Se rechaza una clave diferente sin sustituir la confianza. El transporte puede buscar la misma identidad fijada en otra dirección y reintentar de forma acotada; no acepta automáticamente una clave nueva.

¿Requiere conexión a internet o servicios externos? ▼

El Core y el Registry pueden operar en una red privada. Descargar paquetes y usar clientes de IA, el túnel OpenAI o Cloudflare puede requerir Internet y servicios externos. Revisa qué datos recibe tu cliente.

¿Cómo se auditan las operaciones? ▼

SQLite conserva Activity de las operaciones que la registran. Las mutaciones sensibles requieren evidencia durable y no deben informar éxito si falla la auditoría requerida. No existe una garantía universal de registrar toda petición ni un registro resistente a modificaciones.
